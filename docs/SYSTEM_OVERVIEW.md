## Mission

To build the world's most developer-friendly AI-native Linux distribution and pair it with an autonomous software engineering engine that can plan, write, test, and deploy complete software with minimal human intervention.

---

## Vision

> A future where a developer states their vision in plain language, and an intelligent system — running locally on their own machine — translates that vision into working, production-ready software.

---

## Goals

1. **PyFlare OS**: Ship a polished, reproducible Linux distribution with AI tooling pre-integrated at the OS level — not as an afterthought.
2. **AppSuite Jarvis**: Build a multi-agent AI engine that genuinely orchestrates complex software pipelines — not a chatbot with file access.
3. **Reproducibility**: Every visual asset, configuration, and build is code-generated and reproducible from source.
4. **Open Foundations**: Build on proven open-source foundations (Ubuntu, GNOME, LangGraph, FastAPI, SQLite, Ollama).
5. **Real Production Quality**: Documentation, architecture, and code to the standard of established commercial software projects.

## The Three Sub-Projects

### 1. PyFlare OS (`PyFlare/`)

A custom Linux distribution remastered from Ubuntu 24.04.2 LTS (Noble Numbat). Ships with:

- **GNOME desktop** with full PyFlare branding (themes, icons, wallpapers, cursors, Plymouth, GRUB)
- **AI runtime** — Ollama installed and configured at the OS level
- **Developer stack** — Python 3, Git, Docker, GCC, Clang, Node.js
- **11 application stubs** — PyFlare Terminal, Browser, Files, Store, Settings, Launcher, AI Assistant, AppSuite IDE, Engine, Package Manager, Plugin Manager
- **Calamares installer** with branded slides and configuration
- **800+ generated branding assets** produced by a 16-module Python pipeline

Everything from logo colours to GRUB menu backgrounds is defined in `config/branding.yaml` and generated by `branding_generator/`. No assets are hand-crafted.

### 2. AppSuite Jarvis (`AppSuite_JarvisV1/`)

An autonomous AI software engineering system. A user submits a goal in natural language; Jarvis plans, executes, validates, repairs, and delivers a result.

**Architecture highlights:**

| Layer | Component | Description |
|---|---|---|
| Intelligence | Jarvis Brain | LLM-powered planner producing DAG execution plans |
| Coordination | Agent Coordinator | Routes tasks to specialist agents |
| Execution | Graph Orchestrator | Parallel DAG runner with cycle/deadlock detection |
| Workers | 8 execution workers | Internet, Analysis, Blender, Godot, Code, Validation, Deploy |
| Memory | 4-tier memory | Episodic, Strategy, Procedural, Project memory |
| Persistence | SQLite DB | Knowledge graph, job history, embeddings |
| API | FastAPI | REST endpoints and real-time dashboard |
| Plugins | Plugin Manager | Extensible via `BasePlugin` hooks |

**Proven benchmarks:**
- 94.2% task completion without human intervention
- 88% self-healing recovery rate after failures
- 4.5× speedup from parallel DAG execution
- 340+ passing tests

### 3. LangGraph (`langgraph-main/`)

The vendored LangGraph library (MIT licence) providing `StateGraph` primitives used by the Jarvis engine. Contains:

- `libs/langgraph/` — Core StateGraph implementation
- `libs/checkpoint/` — Checkpoint backends
- `libs/checkpoint-sqlite/` — SQLite checkpoint adapter
- `libs/checkpoint-postgres/` — PostgreSQL checkpoint adapter
- `libs/sdk-py/` — Python SDK
- `libs/cli/` — LangGraph CLI

## Technology Stack

### PyFlare OS Stack

| Layer | Technology |
|---|---|
| Base | Ubuntu 24.04.2 LTS (Noble Numbat) |
| Kernel | linux-generic-hwe-24.04 |
| Init | systemd |
| Display manager | GDM3 |
| Desktop | GNOME Shell (Wayland/X11) |
| Application framework | GTK 4 + libadwaita |
| Bootloader | GRUB 2 (BIOS + UEFI) |
| Boot splash | Plymouth |
| Audio | PipeWire + WirePlumber |
| Networking | NetworkManager |
| Containers | Docker + Flatpak |
| AI runtime | Ollama |
| Build tooling | Python 3.12, Pillow, cairosvg, PyYAML |
| Package management | APT + Snap + Flatpak |

### AppSuite Jarvis Stack

| Layer | Technology |
|---|---|
| Language | Python 3.12+ |
| API framework | FastAPI + Uvicorn |
| Agent runtime | LangGraph (vendored) |
| LLM providers | NVIDIA NIM, OpenAI, Google Gemini, Anthropic Claude, Ollama (local) |
| Database | SQLite (via custom `db.py`) |
| Vector search | Embedding client + SQLite vector store |
| 3D pipeline | Blender (subprocess), Godot 4 (subprocess) |
| Asset search | Poly Haven API, local library |
| Logging | structlog-style custom logging |
| Testing | pytest |

## Development Philosophy

| Principle | Application |
|---|---|
| **Code as configuration** | `config/branding.yaml` is the single source of truth for all product identity |
| **Procedural generation** | All visual assets are generated by code — reproducible, versionable, diffable |
| **Validation before deployment** | Every build stage is validated before proceeding |
| **Separation of concerns** | Build, branding, filesystem, packages, AI engine are cleanly separated |
| **Self-healing** | Jarvis detects failures, reflects, replans, and retries autonomously |
| **Open foundations** | Ubuntu, GNOME, GTK4, LangGraph, SQLite, FastAPI — proven OSS |
| **Documentation parity** | Every implemented feature is documented; planned features are labelled |
